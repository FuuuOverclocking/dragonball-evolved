# 重写一个 VMM：十个设计问题

[目标架构](../vmm-architecture.md) 只记录结论：所有权、线程边界、哪些数据不允许序列化。
结论省略了得出它的过程，也就是当时有哪些可选做法、每种做法会在什么情况下出问题、最后为什么选现在这个。

这个系列把结论还原成问题。每篇从一个具体问题开始，说明约束、可选做法及各自的代价。
参考实现是 Firecracker 和 Dragonball。它们能在生产环境运行，所以它们的选择不是错的，只是受另一组约束。凡是提到它们的做法时，都尽量说明那个约束是什么，以及本项目为什么不再受它限制。
